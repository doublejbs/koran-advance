# 데이터 소스 / API 어댑터 / 라이브 갱신

## 1. 어댑터 레이어

**어댑터 레이어**로 추상화해 공급자 교체를 쉽게 한다
(`DataProvider` 인터페이스: `getTeams()`, `getMatches()`, `getLiveMatches()`).

## 2. 검증 스파이크 결과 (확정)

- **1순위(MVP 채택): worldcup2026 API** — `https://worldcup26.ir`
  - `GET /get/groups` (조별 + 사전계산 순위), `GET /get/games` (경기별 스코어·득점자·상태).
  - **무인증·무료**, 12개 조(A~L) 전부 + 104경기(조별+토너먼트) 완비.
  - 경기별 `home_score`/`away_score`/`finished`/`time_elapsed` 제공 → **순위는 우리가 직접 계산**
    (라이브·시뮬레이터와 동일 로직). 사전계산 순위는 검증용 참고만.
  - 호출 시점에 `time_elapsed:"live"` 경기 확인 → **라이브 동작 실증됨**.
  - ⚠️ 주의: 모든 값이 문자열("3") → 어댑터에서 숫자 변환. 국가명은 EN/FA만 →
    **한국어 국가명은 team_id 매핑 테이블로 자체 보유**. 개인 운영 추정 + `.ir` 도메인이라
    안정성/지속성 리스크 → 폴백 필수.
- **폴백: football-data.org** — 무료 티어에 FIFA 월드컵 포함되나 **스코어 지연 + 10req/분**.
  동일 `DataProvider` 인터페이스 구현체로 준비, 1순위 장애 시 교체.
- 후보였으나 보류: API-Football(무료 100req/일로 라이브 폴링 부족), TheSportsDB(라이브 유료).
- 키가 필요한 공급자의 키는 환경변수 관리. 우선 MVP는 클라이언트 직접 호출,
  CORS/키 노출 문제 발생 시 경량 프록시 검토.

## 3. 라이브 갱신 전략

- 폴링 방식(무료 API에 웹소켓 기대 어려움). 진행 중 경기 있으면 짧게(예 30~60초),
  없으면 길게(예 5분). 요청 제한 고려해 백오프.
- 화면에 "마지막 갱신: hh:mm:ss" 표시, 수동 새로고침 버튼 제공.
